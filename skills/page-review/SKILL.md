# Page review

Page-review serves a page with a comment sidebar. The local server starts on demand.
Use the `review_open`, `review_list`, `review_get`, and `review_reply` MCP tools when
available. Otherwise use the installed `page-review` CLI; `page-review help` explains it.

## Open a review

Call `review_open` with the file or URL as `target`. Supply `project_root` for a dev
server, or when the page belongs to a different source project. Include `context`
describing the page's purpose, source files, and any build command. Generated HTML
must be changed through its source or generator, not hand-edited.

CLI equivalent:

```sh
page-review open /path/to/report.html --project /path/to/project --context "Generated by scripts/report.py; edit the script and rebuild."
page-review open http://localhost:3000/ --project /path/to/project
```

Give the user the returned review URL. They can select text and click Comment, or
Alt+click an element. Provider, model, and effort are in Comments → Agent settings.
Opening the same target preserves its comments. Prefer `--no-browser` if only a URL
is needed. Do not create test comments in a user's review.

## Handle an assigned comment

When a runner names a thread ID, handle only that thread. Read every message using
`review_get` or `page-review get THREAD_ID`. Follow project instructions and use the
thread's `site_context`, `project_root`, and anchor (quote, surrounding text, heading,
and CSS selector) to find the source and understand the request. `context_paths` lists
folders or files the user @-mentioned for context: read them as reference, do not edit them.

Answer questions without changing the page unless a correction is needed. For a
requested change, edit the real source and rebuild if required. If the request is
unclear, ask for clarification. Other runs may be editing the same files: keep edits
targeted and re-read the file before changing it.

When posting replies is authorized by the user's instructions, use `review_reply`
or `page-review reply THREAD_ID "Your answer or a short description of changes"`.
If the user prohibits posting, provide a draft in the current conversation instead.
If the change rewrote the commented text itself, pass its new wording as `anchor_text`
(`--anchor-text "…"` for the CLI) so the comment stays attached and shows the old text.
Keep threads open after replying: only the user resolves them. Do not use `--resolve`.

## Check progress

`page-review status` shows the server, integrations, review links, and pending work.
`page-review status --open` opens its browser dashboard. `page-review log THREAD_ID`
shows the last agent run. If a provider CLI or integration is missing, guide the user
through `page-review setup`; do not install unrelated software or change provider
accounts yourself. Skills do not confer authority to send other communications,
publish, commit, or push.
