One npm package for page-review

Yes. The CLI, local web server, injected comments interface, MCP server, and skill files can ship together. npm installs the package and dependencies; an explicit setup command configures the colleague’s chosen coding-agent clients.

Proposed colleague workflow

The package name below is a placeholder. The setup command is proposed and has not been implemented.

npm install -g @your-org/page-review
page-review setup
page-review open ./report.html

npm exposes executable commands through the package’s bin field, which this project already defines. See npm’s package.json documentation.

What setup would do

  1. Detect supported agent clients and let the colleague choose Claude Code, Codex, or both.
  2. Install the bundled page-review skill into the selected client’s supported skills directory, with an explicit user or project scope.
  3. Register the bundled MCP server using a portable package command, preserving unrelated client configuration.
  4. Configure the preferred provider, model, effort, and runner permissions.
  5. Check prerequisites and explain any missing CLI or sign-in step. Repeated setup should update the same integration without duplicating it.

The local review server already starts on demand. A separate server install or persistent terminal session is unnecessary. Skills teach the agent when and how to open reviews; MCP tools let it read and answer threads; the CLI can open a review directly without the skill.

What is ready, and what remains

Verified on 22 October 2026: npm pack --dry-run --json succeeds, and the package includes the CLI, server, browser client, and MCP source. There is no build step.

Remaining work: add the skill to this repository, implement setup and removal of client integrations, expose a portable MCP entry point, define the published file list, choose the package name and license, and remove private: true when publishing is intended. That flag currently prevents registry publication; it does not mean “publish as a private package.” See npm’s private field documentation.

The current implementation is macOS-oriented: browser opening and the runner’s PATH handling need review before claiming Windows or Linux support. Setup should also handle upgrading a running server so a colleague does not keep using old code after updating the npm package.

Prerequisites and sharing options

The colleague needs Node.js/npm and an installed, authenticated agent CLI for automated replies. The package currently declares Node.js 20 or newer. An installer can help with provider installation, but the colleague must use their own provider account and complete sign-in.

A public scoped package supports ordinary npm installs. A private scoped package limits distribution to authorized users or teams. See public scoped publishing and private packages.

For an initial colleague trial, no registry is required: run npm pack, share the resulting archive yourself, and have the colleague run npm install -g ./page-review-0.1.0.tgz. npm supports installation from a local tarball. The current archive still needs manual skill and MCP setup. See npm install.
