right on your page.

Open an HTML page, select something, and leave a comment. Claude Code or Codex can answer and make changes in the source project. You decide when the thread is resolved.

1. Install and set up

You need Node.js 20.12 or newer, which includes npm. The current LTS version is a good choice. Open Terminal on macOS/Linux or PowerShell on Windows, then run these commands one at a time:

npm install -g page-review
page-review setup

Setup uses a checkbox menu. Use the arrow keys to move, Space to select, and Enter to continue. Choose Claude Code, Codex, or both. We strongly recommend installing at least one skill so your agent knows how to use reviews. You may deselect everything and continue.

Next, pick who answers comments and what they may do. “Edit project files” is the recommended starting point. Some commands may be blocked during unattended runs; full access is a separate choice.

The package includes the review server, command-line tool, agent tools, sample page, and skills. Your AI provider’s app and account are separate. Install and sign in to Claude Code or Codex before using automatic replies. Setup tells you if either CLI is missing. Provider usage is billed by your provider.

Setup connects the selected agents using their own configuration commands. It backs up existing files it replaces. Restart your agent session after setup to discover the new skill and tools. No npm installation hooks edit your agent settings; setup runs only when you ask.

2. Try your first review

page-review demo
  1. The sample page opens in your browser.
  2. Select a sentence and click Comment. To comment on a whole element, hold Alt (Option on Mac) and click it.
  3. Ask a question or describe a change. Your chosen agent works in the source project and replies in the thread. To give it more context, type @ and pick a folder, such as another repository: the agent can read it but not edit it.
  4. Check the result. Click Resolve when you are satisfied. Finishing an agent run does not resolve the thread.

Open your own file

page-review open ./report.html

Use the file’s full path if it is elsewhere. Put paths with spaces in quotes. On many terminals you can drag a file into the terminal to insert its path.

page-review open "/path/to/My report.html"
page-review open ./website

Review a running development server

Start your app normally, then tell page-review its address and the source project directory:

page-review open http://localhost:3000 --project ./my-app

Review generated HTML

Tell the agent where the source lives and how to regenerate the page:

page-review open ./dist/report.html --project . --context "Generated from report.py; edit that file and run python3 report.py"

Review links use localhost and work on your computer. Share the installation instructions with colleagues so they can review their own local files. This is not a hosted collaboration service.

3. Choose your responder

In a review page, open Comments → Agent settings to choose the provider, model, and effort for that site. You can enter a custom model name. Available models and effort levels depend on your provider and account.

To change the default for sites without an override:

page-review runner codex --effort high
page-review runner claude --model opus --effort high

Collect comments without automatic replies, or reset model and effort to provider defaults:

page-review runner none
page-review runner --model default --effort default

You can also ask your agent: “Open this HTML file for review using page-review.” The installed skill teaches it the workflow, and the connected tools let it open pages and work with comments.

If something needs attention

“Command not found”

Open a new terminal after installing Node.js or page-review. Check node --version and npm --version. If npm reports a permissions error, use a user-owned Node installation or ask your IT team to help install it.

The agent does not reply

Run page-review status. Check that your chosen provider’s CLI is found, then run claude or codex to sign in. Rerun setup if tools are not connected. Check the site’s Agent settings: “Off” collects comments without replying. After fixing the problem, add a message to the thread to try again.

The model or a command is rejected

Try the provider’s default model and effort. If a requested command is blocked, run it yourself or change permissions deliberately with page-review runner --permissions bypass. Full access permits unattended commands; use it only for projects you trust.

The browser did not open

Copy the printed localhost address into your browser. On a remote machine, localhost refers to that machine; use your normal SSH port forwarding if needed.

A page is missing

Keep its source folder and development server available. If you moved the file, open its new location with page-review open.

The server needs updating

npm install -g page-review@latest
page-review restart
page-review setup

Wait for active agent work to finish before restarting. Setup refreshes the skills and reconnects the installed package after an upgrade.

Where things are saved

The server runs in the background on your computer and listens on loopback only. The status page is normally http://localhost:4848/; review sites use nearby ports.

  • Settings and server logs: ~/.page-review.
  • Comments on local files: .page-review.json alongside the reviewed HTML files.
  • Claude skill: ~/.claude/skills/page-review/SKILL.md (respects CLAUDE_CONFIG_DIR).
  • Codex skill: ~/.agents/skills/page-review/SKILL.md; its tool connection respects CODEX_HOME.

Set PAGE_REVIEW_HOME or PAGE_REVIEW_PORT before setup to change the data folder or control port. Use the same values for later commands.

Comments and files stay local to this tool. When an agent runs, it uses its provider account and may send relevant content to that provider. A configured webhook sends comment notifications to its destination.

Automated setup

page-review setup --skills claude,codex --runner codex --yes
page-review setup --skills none --runner none --yes

Use --no-mcp to install skills without registering agent tools. For manual MCP configuration, run page-review-mcp or page-review mcp over stdio.

Uninstall

Stop the server, remove its tool connection from each agent you configured, then uninstall the package:

page-review stop
claude mcp remove --scope user page-review
codex mcp remove page-review
npm uninstall -g page-review

Delete the skill folders listed above if you no longer want the agents to discover page-review. Your saved review data remains until you delete it yourself.
